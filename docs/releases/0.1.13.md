# 0.1.13 — Continuous listening

Prepared on `streaming-release`; not deployed or submitted to the store.

- Replaces independent audio uploads with continuous transcription.
- Restores interrupted connections from saved transcript progress, including a cursor inside an audio frame. Unfinished audio stays in a bounded browser buffer.
- Keeps provisional words out of task suggestions, searches and recaps. Recap writes can recover after a lost response without repeating sentences.
- Releases audio inputs immediately on stop and drains the remaining audio before confirming completion.
- Removes the retired upload/decoder implementation, its tests, one-off benchmark runners, FFmpeg, NumPy and unused CLI dependencies. Historical comparison results remain outside the container.

## Verification

Final check counts, package checksum and image sizes are recorded in `0.1.13-checks.json` alongside this note.

The built offscreen capture ran in an isolated Brave profile using synthetic tab audio and a fake silent microphone. A forced disconnect recovered all three reference sentences, emitted provisional results, drained the final audio and released both inputs. The final run submitted 20.424 audio seconds to AWS, estimated at $0.00204. Speaker output is muted in the test harness.

A separate AWS check sent 16.128 seconds of noisy synthetic speech followed by 32 seconds of silence. It finalized text, drained the stalled context at 46.6 seconds, and committed all 48.128 seconds without repeating input between contexts. Recognition still made errors in noisy speech; this verifies transport/finalization, not perfect accuracy or a general latency improvement.

Automated checks cover tasks, Drive/Jira/Confluence search, user isolation, sign-in renewal/revocation, recap-only mode, rejoining, server restart, lost acknowledgments, mid-frame replay, failed persistence, recap outbox recovery, microphone recovery, stopping and restarting capture, and bounded retries/buffering. Linux checks use the locked runtime with external networking disabled.

## Boundaries and cost

Audio is mono PCM16 at 16 kHz in frames of at most 200 ms, approximately 115 MB per audio hour before protocol overhead. Acknowledgments count durably committed samples; they are not frame receipts. There is no per-frame encryption, storage write, or language-model request. Recap sequence numbers remain compatible with the existing recap worker.

The browser retains at most 90 seconds of uncommitted audio, retries an outage for at most 60 seconds, and allows at most five reconnections per capture. Catch-up is paced at up to 2x real time. Recovery requires the offscreen page and its in-memory audio buffer to remain alive; a browser crash cannot restore unsaved audio.

Normal final results retain the recognition context. A 30-second gap without a final result drains and replaces the context; a three-hour context limit also permits long meetings. Old input ends and its results drain before the replacement opens. A meeting remains capped at six audio hours. Timeouts report incomplete capture instead of claiming it was saved.

The normal model-rate difference remains approximately $0.09 per audio hour at the checked regional prices. Replayed unfinished audio and per-session rounding can add transcription charges. Traffic, saved-state operations and server capacity remain usage-dependent. This is not a fixed all-inclusive price or a hard account spending cap. No new worker, server, NAT gateway or load balancer is required. The existing server size and standard CPU-credit mode are preserved.

## Release gate

The server requires `transcribe:StartStreamTranscription` in its own region. The private infrastructure branch adds only this permission, with checks that the resource topology and cost controls remain unchanged.

This release changes the audio protocol. Do not replace the existing production server or website download independently: deployed older extensions still require their existing server. Use a coordinated migration or keep the previous endpoint available until those installations update. Production and the public package remain unchanged by this branch.

A real Google Meet capture check and a two-person Zoom browser audio/reconnect/recap check remain required before public promotion. Zoom stays a browser preview; Zoom desktop is unsupported. Local fixtures and synthetic browser/AWS checks do not replace those live-call checks or establish production capacity.
